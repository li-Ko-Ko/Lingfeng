## 表示法 / Notation

从和弦轨保存进行会记录指定低音及转位；右键“检索和弦进行”按所选和弦时间顺序只提取根音，各和弦以本次所选主音解释，Ctrl 不连续选择也适用。低音与转位参与保存和应用，但不参与根音匹配。单个 I/3 与 I、i7 都按 I 检索，I/3–IVmaj7/6 则按 I–IV 检索，并允许候选进行中夹有其它和弦。

Capturing chord blocks stores their specified bass and inversions. Find chord progressions extracts only chronological roots from the selection, against the selected tonic; noncontiguous Ctrl selections are supported. Bass and inversions are saved/applied but ignored by root search. I/3, I and i7 all search as I; I/3–IVmaj7/6 searches as I–IV with optional chords in between.

- 转位使用明确的低音音级：原 I⁶ 转为 I/3，I⁶₄ 转为 I/5，V⁶ 转为 V/7，vi⁴₂ 转为 vi7/5。I6 在伶风输入中仍表示大六和弦，不能与数字低音转位混用。
- 副属保留功能表示：V/vi；若还指定低音，最后的数字相对原主音，例如 V/vi/#5 在 C 大调生成 E/G#。名称中的数字低音是说明文字，不解析为音乐。
- 页面检索路径中的 b4 表示借用小调的 iv，不是 bIV；本表按谱例实际性质写作 iv。
- Inversions use explicit bass degrees: I/3, I/5, V/7 and vi7/5. I6 input continues to mean an added-sixth chord. An applied chord can end in an original-key bass degree: V/vi/#5 is E/G# in C major. The source path b4 denotes borrowed iv, not a lowered IV root.

应用时保留预设罗马数字所写性质，以所选主音预览字母名称；所有目标区域均按这个主音生成，不随谱面调号改变。运行时使用 PyChord 校验及移调，所有 21 组均受支持。原有其它 5 组继续保留，默认共 26 组；用户可在“管理和弦进行”中修改自己的目录。

Application previews letters and generates all destination regions using one selected tonic, preserving the qualities written in the recipe. PyChord validates/transposes all 21 supported recipes. Five other existing recipes remain, making 26 defaults. Users manage their own library in Manage chord progressions.

## 局部主音（0.44） / Local tonic

保存与应用默认使用起始和弦所在小节主音；检索所选和弦也以首个所选和弦为起点，从设置打开检索则取游标小节。下拉按音高排列，标号为 1–7 加升降号，1 为该小节主音。C 调 Gm–C–F 在 C 主音下为 v–I–IV，选择 F 后为 ii–V–I。主音是本次操作参数，不写进进行库，也不改变谱面调号。指定低音及副属关系相对所选主音解释。

库内添加/修改只编辑罗马数字及可选名称。检索可输入相对罗马数字，也可输入实际和弦名；选择 F 时 Gm C F 按 II–V–I 检索（忽略性质）。从和弦轴打开检索后，改主音会自动重算条件；手动编辑条件后，罗马数字保持相对关系，实际和弦名继续按所选主音转换。

Capture, Apply and Search use a pitch-ordered selector labeled with modal degrees and accidentals. Tonic is an operation parameter, never part of the library recipe or score key. C-relative v–I–IV and F-relative ii–V–I both describe Gm–C–F. Add/Edit stays purely Roman. Searches accept either relative Roman numerals or literal chord names; changing tonic reinterprets the selected chords or letter-name query.
